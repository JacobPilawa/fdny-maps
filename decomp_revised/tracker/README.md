# Project tracker

This directory keeps the progress evidence that feeds the local dashboard.

- `functions.csv` is rebuilt from the fresh Ghidra exports. It includes body-bearing functions and external import stubs. Body-function totals are Ghidra's current boundaries, not a claim that every routine has been discovered.
- `binaries.csv`, `imports.csv`, `exports.csv`, and `sections.csv` hold PE module, section, and dependency facts from GNU `objdump`.
- `legacy_crosswalk.csv` joins prior indexed decompiler exports to current exact entry addresses. These are address-only joins: the prior index does not bind every export to a verified EXE hash. Legacy C-like exports are evidence artifacts, not recovered original source.
- `milestones.csv` tracks project outcomes separately from function counts.
- `function_reviews.csv` binds reviewed EXE functions to fresh pseudocode and behavior notes; these entries appear as `triaged` in the function atlas.
- `genesis_function_reviews.csv` separately tracks hash-pinned Genesis.dll engine functions reviewed for this port. These are not included in the EXE-only function dashboard count.
- `progress_history.csv` stores cumulative review snapshots for the dashboard time series.
- `genesis_api_crosswalk.csv` tracks selected EXE imports and their callers into Genesis.
- `level_map_inventory.csv` tracks all catalog entries and local BSP variants, their rescue-object counts, file hashes, and current typed-export status.
- `rescue_mission_coverage.csv` tracks all eight rescue-mode catalog scenarios (Training plus the seven campaign rescues), joins their scene/script hashes and authored fire/victim/trigger/PathPoint counts, and separates geometry inspection from playable-port and parity status. It does not replace the 12-entry/17-BSP inventory.
- `rescue_actor_inventory.csv` indexes every authored PlayerRescue, FireRescue, VictimRescue, VictimAltSpot, and PathPoint record in all 17 local BSPs. It preserves each BSP hash, entity index, ordered raw epairs, fire keyframes, script fields, victim types, and authored locations. Regenerate it with `python3 tools/build_rescue_actor_inventory.py`; it is map data, not runtime spawn or parity evidence.
- `scene_load_coverage.csv` is generated by running the standalone C++ `SceneData` loader in inspect mode for each local BSP export; it records loaded hashes, entity/mesh/collision counts, spawn positions, and unresolved texture paths. It does not claim rendered or gameplay parity.
- `scene_property_matrix.csv` aggregates per-class property presence across the hash-matched BSP exports without copying authored values. Regenerate it with `python3 tools/summarize_scene_contracts.py` after refreshing map exports.
- `victim_resource_crosswalk.csv` joins every authored victim type to `victims.srf`, `rescue.rrf`, local ACT-file availability, unknown-type fallback, runtime renderer model IDs/ACT paths, and the material-variant rule. Regenerate it with `python3 tools/build_victim_resource_crosswalk.py` after refreshing map exports.
- `actor_asset_inventory.csv` records hash-pinned ACT decode coverage, mesh/texture/motion counts, material slots, resolved actor sound cues, and separate declared-resource versus runtime-renderer ACT paths. It also records the source-mapped per-model material cycling rule. Regenerate it with `python3 tools/export_victim_actors.py`; decoded review JSON/OBJ/PNG assets stay in ignored `.local/actor_exports/`.
- `evidence/genesis-boundary/` and `evidence/runtime-loop/` hold hash-pinned query outputs, pseudocode, and instruction evidence.
- `genesis_function_reviews.csv` and `evidence/genesis-boundary/` record 25 hash-pinned shipped Genesis.dll collision, GBSP, bitmap, and actor-material functions. See `evidence/runtime/genesis_collision_path.md` and `evidence/runtime/genesis_render_asset_path.md` for interpretation and limits.
- `evidence/fire-spread/` holds fresh hash-pinned FireRescue random-spread,
  spray suppression, HoseSpray contact, exposure-volume, Player message, and
  burn/passout traces. Selected earlier code and the tagged suppression oracle
  are preserved separately under `../reference/legacy-evidence/fire-spread/`.
- `evidence/victim-resources/` holds hash-matched evidence for victim catalog order, unknown `D_Type` fallback, actor resource mapping, model-14 renderer selection, and per-model material variation.
- `generated/` contains the raw function and PE-analysis outputs. When a saved Ghidra MCP session has newly defined boundaries or renamed functions, the affected function rows are synchronized from that program before the next full export.
- `summary.json` and `../dashboard/index.html` are regenerated by `tools/build_tracker.py`.

After rebuilding `fdny-scene-viewer`, refresh the package-load ledger with
`python3 tools/build_scene_load_coverage.py`. The HTML dashboard remains a
separate, occasional refresh; this CSV records map coverage directly.

Stop the running GhidraMCP server before refreshing the project database. Run `tools/refresh_inventory.sh` after changing analysis inputs or Ghidra analysis. To export the current saved database without reanalyzing, run `tools/export_inventory.sh`. Restart the server afterward with `tools/ghidra-mcp/start_server.sh`. If startup reports that the project is locked, check `http://127.0.0.1:8089/check_connection` before trying another instance; one service may already be using the project. The current Codex MCP tool list may require trusting/reloading this project to expose the stdio bridge in-chat.
