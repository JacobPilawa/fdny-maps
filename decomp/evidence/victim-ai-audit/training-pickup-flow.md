# Training victim pickup and exit flow

Read-only Ghidra exports are preserved alongside this note. Static owner/message order is partly established; player movement's order and a complete native gameplay match are not. Exact player box bounds and the victim callback's inclusive AABB predicate are recorded in `player-pickup-bounds.md`.

## Source-backed path

- Victim proximity callback `0045A070` rejects victim states 5 and 6, considers another entity with type 1, checks an AABB overlap using a value derived from victim `+0x150+0x1c` (fallback 60 when the helper result is below 1), then queues message `0x7532` to the player with the victim pointer. See `runtime-callbacks/0045a070_FUN_0045a070.c`.
- Player bounds from `0044D550`, crouch/uncrouch height changes from `0044BCB0`/`0044BCE0`, and the world-origin callback at `0049DB90 → 0049D790` are now mapped. Training's two victims author radius 60. Native code has the isolated source-derived predicate and boundary/gate harness; it is not connected to an unverified update loop. See `player-pickup-bounds.md`.
- The victim's primary vtable is `004E25B8`; its `+0x48` entry is `0045A070`. Owner manager `0049BD20` invokes object `+0x48` callbacks during its category passes. In owner update `00429520`, those passes precede staged-entity admission and message drain `0049B610`, so this callback can enqueue `0x7532` for delivery in the same owner update.
- Victim child updater `0045BEA0` is state-gated: state 5 returns, state 6 runs `004599B0`, and state 7 runs movement `0045B220 → 0045AE50` before animation. Ghidra shows that generic victim scripts can enter state 7 through the `roam` command handled by `0045CDB0`; the preserved Training script/entity sources do not contain that command, so Training reachability is unproven. The child-updater schedule remains unknown. See `victim-state-updater.md`.
- Player message handler `00453A70` routes `0x7532` to `00450440`. If the carry field at player `+0x3534` is empty, `00450440` stores the victim pointer and calls `0045BEF0` before its UI/state work. The victim state setter and message handler exports are under `rescue-flow/`.
- Training entities 191 and 194 bind `pickup` to the authored `Cmd3b`/`Cmd3c` hints and set the shared `gotvictim` variable. `training.evs` defines those hints as directions to the exit.
- Training exit bounds triggers bind `touch: tell player escape`. Player script handler `00451870` routes `escape` through `004513A0` to `00451160`. With a carried victim, `00451160` increments rescue statistics, releases the victim through `0045C000`, clears player `+0x3534`, and calls `004504C0` to check/activate exits.
- Release transform `0045C000` sets victim state 6. It reads the player frame via vtable `+0x18`, copies frame `+0x04` negated to victim `+0x28`, then reads frame `+0x1C` negated to victim `+0x40`. It calls virtual slot `+8` on the victim frame at `this+0x24` with `(0, 1.0f, 0)`. The vtable resolves to wrapper `0042BD50`, which forwards that vector to frame updater `00496210`; the updater sets the frame's Y axis to world-up and rebuilds an orthonormal basis. The routine then reads the post-call frame `+0x1C`, multiplies each component by 5 and then by 24 as separate float operations, reads the player frame a third time, and stores frame `+0x28` minus that vector at victim `+0x4C`. It calls `0049DA00` for floor placement, sets actor flag mask `0x400` on the `+0x170` subobject through `00481140`, dispatches actor event `rescue`, writes `+0x1F8=150`, `+0x1F4=global time+2000`, `+0x1F0=global time+2150`, `+0x1FC=1`, then calls `00480D40` (which clears byte `+0x30` in that subobject). The flag's render/visibility meaning remains unverified. See `evidence/victim-ai-audit/release-frame-method.md`, `evidence/startup-factories/0045c000_FUN_0045c000.c` and `evidence/startup-factories/004599b0_FUN_004599b0.c`.
- Victim actor updater `0045BEA0` reaches `004599B0` only for state 6. That routine returns until unsigned deadlines `+0x1F4` and `+0x1F0` are both strictly earlier than the current tick and `+0x1F0` is not `UINT32_MAX`. When due, it optionally calls the sound helper for `+0x154` if `+0x1F4` is nonzero, clears `+0x1F4`, subtracts 5 from `+0x1F8`, then either clears `+0x1FC` and sets `+0x1F0=UINT32_MAX`, or schedules `+0x1F0=current time+remaining` and toggles `+0x1FC`. It passes the toggle to `00481140`, which calls `geWorld_SetActorFlags` with mask `0x400` or `0`; the flag's render/visibility meaning has not been verified. The updater's live schedule is unknown, so these timers are not tied to native render frames.

## Native gap and limit

`src/main.cpp` currently dispatches bounds-trigger and PropModel touch events, but has no victim `pickup` dispatch or player `escape` host command. Movement routine `00452570` is slot 0 of the Player secondary subobject at `+0x140` (vptr `004E1C40`, installed by `00453D50`), not a primary-Player callback; its direct code xrefs do not reveal its scheduler. The app's `+0xA0` registered-list pass calls each member's vtable `+0x70`; the secondary Player table's `+0x70` entry `00453CF0` is a type/name helper, not movement. The list's Player membership and movement's relative order to victim proximity remain unresolved. Victim constructor `0045DDD0` installs updater `0045BEA0` at slot 0 of child subobject vtable `004E25B0` at `+0xD4`, and calls base initializer `004799B0`; its `0049D330(this,1)` membership registration applies to the parent victim. The xref scan finds `0045BEA0` only as a word in that child vtable, and the owner `+0x3C4` callback queue has no proven insertion for the child. A dynamic registration not found by these scans remains possible, so the updater schedule is unresolved. The actor flag `0x400` meaning is also unknown. Preserve these gaps when connecting gameplay.

## Additional state path retained for full-run work

It sets victim state 4, chooses an animation through `00480EA0` after one `00404B30` bounded draw (`bounded(3)`, speed 1 when victim `+0x180 == 6`; otherwise `bounded(victim+0x180)`, speed 0.2), rebuilds victim frame fields from the player's frame, places the victim with `0049DA00`, enables the actor subobject through `00481140`, and dispatches actor event `passout`. `0044FF10` clears the player's carry pointer afterward. Its other branches include state- and parameter-gated `herodown` counting/spawning.
