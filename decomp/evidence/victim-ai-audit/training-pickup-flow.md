# Training victim pickup and exit flow

Read-only Ghidra exports are preserved alongside this note. Static owner/message order is partly established; player movement's order and a complete native gameplay match are not. Exact player box bounds and the victim callback's inclusive AABB predicate are recorded in `player-pickup-bounds.md`.

## Source-backed path

- Victim proximity callback `0045A070` rejects victim states 5 and 6, considers another entity with type 1, checks an AABB overlap using a value derived from victim `+0x150+0x1c` (fallback 60 when the helper result is below 1), then queues message `0x7532` to the player with the victim pointer. See `runtime-callbacks/0045a070_FUN_0045a070.c`.
- Player bounds from `0044D550`, crouch/uncrouch height changes from `0044BCB0`/`0044BCE0`, and the world-origin callback at `0049DB90 → 0049D790` are now mapped. Training's two victims author radius 60. Native code has the isolated source-derived predicate and boundary/gate harness; it is not connected to an unverified update loop. See `player-pickup-bounds.md`.
- The victim's primary vtable is `004E25B8`; its `+0x48` entry is `0045A070`. Owner manager `0049BD20` invokes object `+0x48` callbacks during its category passes. In owner update `00429520`, those passes precede staged-entity admission and message drain `0049B610`, so this callback can enqueue `0x7532` for delivery in the same owner update.
- Victim root slot `+0x14` points to thunk `00459990`, which passes child `+0xD4` through shared updater `00470740` to child slot 0 / `0045BEA0`, subject to the root and wait gates. The child updater is state-gated: state 5 returns, state 6 runs `004599B0`, and state 7 runs movement `0045B220 → 0045AE50` before animation. Ghidra shows that generic victim scripts can enter state 7 through the `roam` command handled by `0045CDB0`; the preserved Training script/entity sources do not contain that command, so Training reachability is unproven. The recurring caller and cadence for root slot `+0x14` remain unknown. See `victim-state-updater.md` and `victim-child-update-scheduling-audit.md`.
- Training's known victim state transitions are initial state 4 from actor initialization `0045B690`, pickup state 5 through `0045BEF0`, then rescue-release state 6 through `0045C000`. Pickup stores world actor flags word 0, which fails the normal renderer's submission gate; rescue release stores `0x400`, which passes it. State 7 remains documented for full-game coverage but has no identified Training entry; actor-update scheduling still blocks exact animation and post-release timing.
- Player message handler `00453A70` routes `0x7532` to `00450440`. If the carry field at player `+0x3534` is empty, `00450440` stores the victim pointer and calls `0045BEF0` before its UI/state work. `0045BEF0` sets victim state `+0x120=5`, then `00481140` stores actor flags word 0 for the subobject `+0x170`; this excludes normal-world render submission in the bundled Genesis renderer. It then dispatches `pickup` on child `+0xD4`; Training's victim handlers show the authored hint and set `gotvictim`. Rescue helper `0045C000` later stores actor flags word `0x400`, which passes the normal render gate. Exact DLL evidence and reflection/collision limits are in `actor-render-flags.md`. The state setter and message handler exports are under `rescue-flow/`; `0045BEF0` was also rechecked in Ghidra's preserved EXE project.
- Training entities 191 and 194 bind `pickup` to the authored `Cmd3b`/`Cmd3c` hints and set the shared `gotvictim` variable. `training.evs` defines those hints as directions to the exit.
- Training Player entity 115 authors `setrescuebot 0`; handler `00451870` parses decimal zero and stores false at Player `+0x32e4`. That is the map's RescueBot-off setting; exact startup callback timing is unverified. The separate RescueBot route `00454750 → 0045BF70` is documented in `victim-state-updater.md` for full-game coverage.
- Training exit bounds triggers bind `touch: tell player escape`. Player script handler `00451870` routes `escape` through `004513A0` to `00451160`. With a carried victim, `00451160` increments rescue statistics, releases the victim through `0045C000`, clears player `+0x3534`, and calls `004504C0` to check/activate exits.
- Release transform `0045C000` sets victim state 6. It reads the player frame via vtable `+0x18`, copies frame `+0x04` negated to victim `+0x28`, then reads frame `+0x1C` negated to victim `+0x40`. It calls virtual slot `+8` on the victim frame at `this+0x24` with `(0, 1.0f, 0)`. The vtable resolves to wrapper `0042BD50`, which forwards that vector to frame updater `00496210`; the updater sets the frame's Y axis to world-up and rebuilds an orthonormal basis. The routine then reads the post-call frame `+0x1C`, multiplies each component by 5 and then by 24 as separate float operations, reads the player frame a third time, and stores frame `+0x28` minus that vector at victim `+0x4C`. It calls `0049DA00` for floor placement, sets actor flags word `0x400` on the `+0x170` subobject through `00481140`, dispatches actor event `rescue`, writes `+0x1F8=150`, `+0x1F4=global time+2000`, `+0x1F0=global time+2150`, `+0x1FC=1`, then calls `00480D40` (which clears byte `+0x30` in that subobject). Word `0x400` passes the bundled Genesis normal renderer's actor-submission gate. See `actor-render-flags.md`, `evidence/victim-ai-audit/release-frame-method.md`, `evidence/startup-factories/0045c000_FUN_0045c000.c` and `evidence/startup-factories/004599b0_FUN_004599b0.c`.
- Victim actor updater `0045BEA0` reaches `004599B0` only for state 6. That routine returns until unsigned deadlines `+0x1F4` and `+0x1F0` are both strictly earlier than the current tick and `+0x1F0` is not `UINT32_MAX`. When due, it optionally calls the sound helper for `+0x154` if `+0x1F4` is nonzero, clears `+0x1F4`, subtracts 5 from `+0x1F8`, then either clears `+0x1FC` and sets `+0x1F0=UINT32_MAX`, or schedules `+0x1F0=current time+remaining` and toggles `+0x1FC`. It passes the toggle to `00481140`, which stores actor flags word `0x400` or `0`; these alternate normal-world render eligibility. The updater's live schedule is unknown, so these timers are not tied to native render frames.

## Native gap and limit

`src/victim_rescue.h` now models the source-backed transaction after Player receives message `0x7532`: Player message gate, empty-carry gate, carry-pointer store, victim state 5, actor flags word 0, `pickup` event dispatch, and a post-event Player-effects hook, in Ghidra order. In Genesis.dll, flags word 0 suppresses normal-pass render submission while leaving actor-list membership intact; see `actor-render-flags.md`. `--victim-pickup-message-check` checks handler gates and callback order; this is a native control-flow check, not an original-binary runtime oracle. The helper is not connected to a native proximity producer or main-loop schedule, and the post-event Player effects and actor rendering are not implemented. Do not claim a playable pickup from this component.

Movement routine `00452570` is slot 0 of the Player secondary subobject at `+0x140` (vptr `004E1C40`, installed by `00453D50`), not a primary-Player callback; its direct code xrefs do not reveal its scheduler. The app's `+0xA0` registered-list pass calls each member's vtable `+0x70`; the secondary Player table's `+0x70` entry `00453CF0` is a type/name helper, not movement. The list's Player membership and movement's relative order to victim proximity remain unresolved. Victim constructor `0045DDD0` installs root vtable `004E25B8` and child vtable `004E25B0` at `+0xD4`; root `+0x14` reaches child updater `0045BEA0` through `00459990 → 00470740`, subject to the source gates. Its `0049D330(this,1)` membership registration applies to the parent victim, and the owner `+0x3C4` callback queue has no proven insertion for the child. The recurring root-slot caller/cadence remain unresolved. The actor flags' effect in the Genesis normal render pass is mapped; initial Training flags and other render passes remain open. Preserve these gaps when connecting gameplay.
