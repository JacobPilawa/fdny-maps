# `0044FF10` herodown and cleanup tail

`player_herodown_tail.h` begins after the carried-victim `0045C1A0` transaction has returned. The preceding `0044FF10` preamble and victim drop remain in `victim_passout.h`; this tail does not duplicate them. It performs no RNG draw, clock query, or event dispatch.

The independent branch runs only when mode `DAT_00502AAC+0x6E4`, field `+0x2C`, equals 2 and the caller's byte argument is zero. It counts current type-2 entities whose script name compares case-insensitively equal to `herodown` and whose state is 4 or 7. The native helper uses ASCII case folding, equivalent for the authored ASCII name; it does not claim full CRT `_stricmp` locale/byte parity. When the count is below 3, the source allocates/zeroes a 0x34-byte descriptor, copies Player position, and stages a `POFighter` / `herodown` request for class name `RCS_VictimRescue`; the recovered raw descriptor values include word0 1000, word6 0, word7 20.0, and lookup argument 100. The source also formats signed `%i` from `(Player+0x3428)-1` using the current 32-bit bit pattern. This is the string suffix appended to `POFighter`; the combined result is copied into descriptor word 4. Assembly `00450104..0045011e` exposes the decrement/push vararg omitted by the decompiler. Fresh decompilation confirms `004040E0` uses `00403E40`, which copies its base string, appends the second argument through `00401D00`, then assigns the combined string to its output; thus this call constructs `POFighter` followed by the formatted signed count-minus-one. The component passes those exact source values to an opaque spawn adapter rather than reimplementing engine/resource staging. After staged enqueue (`0049D4C0`), it increments the shared Player `+0x3528` count, updates `Rescues` through `00486920`, then increments the local down count. This increment wraps as the source 32-bit word does. It logs `Firefighters down = <count>` whether or not a spawn was needed, when this branch is enabled.

The helper's cleanup tail is unconditional after that optional branch: if Player `+0x357C` is nonzero and equals 4, the source invokes the array-bounds diagnostic helper when `+0x3568` is below 5, then continues to read the nested cleanup state. The component's diagnostic callback is nonthrowing; it does not turn this check into a return/abort gate. The source calls `00463370(entity,2)` only when the nested state is 3. All nonzero states then call `0044C360`. Finally every path calls `0044CD10` followed by `00456F70(Player+0x5F4)`. These callbacks preserve opaque engine/UI state changes. `00456F70` copies current global `DAT_00502AFC` into its `+0x2B38` timestamp and performs its remaining status changes; the component does not sample or invent clock time.

The carried-victim preceding RNG draw is documented in [`passout-component.md`](passout-component.md); the tail adds no draws.
