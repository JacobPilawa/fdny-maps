# Shared victim state and composed delivered transactions

`victim_transactions.h` joins the recovered delivered pickup and escape routes using one shared carried pointer, pickup-effect timestamp, rescue counters, actor state/flags, frame and animation. It has no per-frame tick or proximity producer. Required service callbacks expose unresolved engine/UI boundaries and fail if absent; their omission is not treated as a completed gameplay action.

Pickup executes the source flags write and synchronous EVS event before entity carry mode, the live Player `+0x18C` read, storage/status action 1, zone membership rebuild and final clock sample. The field reader variant was added because evaluating `+0x18C` before the entity helper would snapshot it too early. Fixed-field standalone checks retain the original convenience wrapper.

Escape executes rescue statistics, concrete frame/floor operations, flags and synchronous rescue event, timer/actor reset, status action 2, the recovered `004541A0` deadline RNG consumer, carried-pointer clear, entity carry reset and exit bookkeeping. The deadline reads are separately sequenced after status action 2, and the same shared `Random` is used. `00480D40` clears actor subobject byte `+0x30`; the composed native animator clears its matching playing state.

The native scene now stores each victim in `VictimRuntimeActor`. Startup fills the selected floor position and existing source-traced heading basis; scene animation and normal render gating use this record. The renderer's dynamic root overload reads that frame rather than immutable spawn placement. The initial roots compare against the previous source-traced wrapper, and two-frame native rendering draws 90 textured mesh groups with OpenGL error 0. Final skinned-vertex parity and general non-unit entity-scale rendering remain open.

Luna supplied `carry_entity_mode.h` and `victim_status.h`. Carry mode preserves the type-3/type-8 raw field writes, source diagnostic order and false-only world-model flags API. Null-model API behavior remains unresolved. Status actions share the actual `RescueExitState` counters; its sentinel count helper now stores zero before enumeration, matching `0044FBA0`. The status test was changed from a duplicate counter fixture to the real shared state/`Extended` types.

`--victim-transactions-check` composes both Training victims from actual startup state. It dispatches their preserved EVS pickup scripts, uses real native BSP release traces, rebuilds memberships, executes the status and exit cores, updates supplied statistic records, checks animation/flags/state, rejects repeated pickup and empty escape, and verifies one source deadline draw per rescue. Source phase services for UI and carry-mode engine effects are controlled inputs in this check; it does not claim their presentation or recurring schedule is complete. Statistic update modes in this fixture are supplied test configuration, not assumed original resource configuration.

All 15 CTest checks pass, plus original animation (54 selections/432 updates), pose asset consistency and startup checks. The two existing view parity failures remain documented and unmodified. No original full Training event/RNG replay has been captured.

Next work is to bind original actor proximity/route delivery and root scheduling to this state, supply the actual status/engine services and `+0x343C` source producer, add continuous carry/passout integration, and compare integrated source traces. The scene still does not automatically pick up or rescue victims. The composed routes remove duplicated state and provide the integration boundary; full Training remains unfinished.
