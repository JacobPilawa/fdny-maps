# Training door motion audit

Read-only Ghidra 12.0.4 audit of the preserved `FDNYFirefighter.exe` project on 2026-10-11. The BModel script handler and motion helpers were inspected with `DecompileFunctions.java`; the call paths are summarized below. No live gameplay capture was used.

## Source behavior

- `RCS_BModel` script handling enters at `0043E680`. Its handler receiver is the ScriptActor subobject at object `+0x24`. `settime` writes receiver `+0x1B4` (BModel base `+0x1D8`); `settimescale` writes receiver `+0x1B8` (BModel base `+0x1DC`). Training's shared `Door` macro sets the motion timescale to `3.0`.
- BModel bounds are built at `0043B7A0` by unioning each child model's runtime bounds. Genesis `1003BBA0` initializes those from the BSP root-node record; the helper `004818C0` then adds the scalar at `004E2928` to each min and subtracts it from each max. A read-only Ghidra scalar query confirms `004E2928` is exactly `128.0f`. These contracted bounds are the values `openaway` reads, not the entity AABB or serialized GFX_Model extents directly.
- The `openaway` command calls `0043D6A0`. If BModel state `+0x70` is `4`, it clears the ScriptActor queue/wait and appends the string `openaway`, then returns without directly changing state. Otherwise it reads the player position and iterates child model IDs at `+0x1C0` (count `+0x1C4`). For each model it gets motion path 0 and continues only if the rotation path has two keys. It constructs the relative rotation from keyframe 0 transpose times keyframe 1. It forms two XZ corners from the root bounds, selects their near-to-far direction relative to the model rotational center (the first corner wins a distance tie), normalizes that direction, applies the relative rotation, and dots it with player position minus rotational center. A nonnegative dot transposes keyframe 1 and calls `gePath_ModifyKeyframe` with rotation flag 1; the threshold at `004DC50C` is exactly `0.0f`. It then writes BModel state 3. The modified endpoint is retained in the motion path.
- The `close` command calls `0043DA70`. If state `+0x70` is not `3`, it writes state `4` and returns. If state is `3`, it clears the ScriptActor queue/wait and appends `close`; this branch does not directly write a new state.
- The shared ScriptActor updater `00470740` processes at most one queued command per callback. This makes the queue effects source-backed but does not reveal how often BModel motion advances or when the queue owner is called relative to player and trigger callbacks.

## Training and native boundary

All 20 Training `*Door` BModels have one `C_AnimModel` child matching the entity model ID. Their extracted model motions have two rotation keys at times 0 and 1, identity start rotation, nonzero Y-only end rotation, and two zero translation keys at times 0 and 1. The BSP `%Model%` origin and the extracted collision model origin match at binary32 precision for all 20 doors. Ghidra also verifies that the origin reaches the pivot used at runtime: EXE `00495310` passes the BSP to `geWorld_Create`; Genesis loader `1003E810 → 1003B8C0` parses the file, and model initializer `1003BBA0` copies serialized 0x50-byte `GFX_Model` record offsets `+0x20..+0x28` into runtime WorldModel offsets `+0xA4..+0xAC`. `geWorld_GetModelRotationalCenter` (`1003C070`) reads those fields. `extract_gbsp.py::parse_models` independently places the serialized origin at `+0x20`.

The Genesis loader's runtime bounds are root-node bounds from the BSP's 0x2c `NODES` records; `004818C0` contracts them by 128. They are not the already-extracted GFX_Model mins/maxs. After contraction, every max and all but twelve min components match the extracted extents exactly. For models 66–71, X-min and Z-min are each `-0.00048828125` lower, the measured float32 rounding from the serialized root-node bounds. The loader trace and per-door comparison are recorded in [`training-door-bounds-loader-audit.md`](training-door-bounds-loader-audit.md). **Correction:** the first implementation incorrectly contracted the extracted GFX_Model extents a second time, producing inverted bounds; it now follows the Ghidra-verified root-node lookup. `./run.sh --door-asset-check` checks each door's root index, contracted bounds, known six-model rounding pattern, child/model mapping, and motion shape.

Native `Door::openAway` now uses the Ghidra-derived contracted root-node bounds, nearest-corner direction, relative authored rotation, and zero-dot branch. Its keyframe endpoint comes from extracted motion data; the source's endpoint transpose is represented by quaternion conjugation followed by normalization. This is a source-derived code path, not an original-runtime numeric comparison. `Door::update` still starts from proximity, advances/reverses a local fraction at `dt * 3`, and applies collision rotation directly. It does not yet run the original EVS/ScriptActor state and queued-command sequence. Exact trigger reachability, update cadence, time advancement, event ordering, and collision/render parity remain open. The contact producer's owner-manager order and local `touch → touching → untouch` conversion are documented in [`training-bmodel-contact-scheduling-audit.md`](training-bmodel-contact-scheduling-audit.md); its dynamic placement relative to that producer is still unknown.

The BModel callback's internal time advance and explicit Genesis path sample are traced in [`genesis-motion-cadence/genesis-model-motion-update-ghidra-audit.md`](genesis-motion-cadence/genesis-model-motion-update-ghidra-audit.md); its regular invocation cadence is still unresolved. The local `touch → DoorOpen`/`untouch → queued DoorClose` order and the unresolved producer/updater scheduling boundary are recorded in [`training-door-contact-event-order-audit.md`](training-door-contact-event-order-audit.md). The pivot mapping is source-verified as above. Quaternion conjugation plus normalization follows the source's XForm transpose plus `gePath_ModifyKeyframe(..., flags=1)`, but the two native forms have not been compared bit-for-bit against Genesis DLL execution.

Raw command implementations are available in the Ghidra project at `0043E680`, `0043D6A0`, and `0043DA70`. The native queue evidence is in [`training-script-queue-audit.md`](training-script-queue-audit.md); the concise command table is in [`training-script-command-audit.md`](training-script-command-audit.md).
