# Native player pain deadline slice

`src/player_pain_deadline.h` isolates the branch in `00451640` after the exposure threshold has been reached. The raw listing at `evidence/fire-update/player-exposure-assembly.txt` shows an unsigned `JBE` gate against Player `+0x390`; the due branch queues `RC_Pain` before calling `00498B30(1000,2500)`. `00498B30` calls `00404AC0` once. The x87 instructions then add the unsigned current millisecond clock to that range result, pass it to `004B9400`, and store the low dword at `+0x390`. The helper's assembly and explanation are in `random-conversion-assembly.txt` and `timer-semantics.md`.

The native component uses the existing `Random` shared stream and `Extended` 64-bit-significand arithmetic. Its explicit `RC_Pain` host service receives that same RNG before the deadline draw, since the key resolves via `004897C0 → 00488E30 → 00488D40`; the sound-selection routine can consume one draw and a repeat-avoidance draw. The component owns exactly one additional draw for the pain deadline after the service returns. This leaves sound lookup/playback as a host service and does not connect the FireRescue producer, exposure accumulation, or player callback scheduling.

`player_pain_deadline-check` checks before/equal/after deadline behavior, verifies no service or draw when not due, observes an injected service draw before the single deadline draw, and checks unsigned 32-bit deadline storage including a high-bit clock. This is a native control-flow check only: no original `00451640` P-code fixture was produced, so this is not a direct original-vs-native parity claim.
