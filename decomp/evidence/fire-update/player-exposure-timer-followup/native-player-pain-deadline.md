# Native player pain deadline slice

`src/player_pain_deadline.h` isolates the branch in `00451640` after the exposure threshold has been reached. The raw listing at `evidence/fire-update/player-exposure-assembly.txt` shows an unsigned `JBE` gate against Player `+0x390`; the due branch resolves `RC_Pain` before calling `00498B30(1000,2500)`. The x87 instructions add the unsigned current millisecond clock to that range result, pass it to `004B9400`, store the low dword at `+0x390`, and only then call `00486980` with `"Serious Burns"` and value `1`.

The native component uses the existing `Random` shared stream and `Extended` 64-bit-significand arithmetic. Its explicit `RC_Pain` host service receives that same RNG before the deadline draw, since the key resolves via `004897C0 → 00488E30 → 00488D40`; the sound-selection routine can consume one draw and a repeat-avoidance draw. The generic selection is already implemented by `Random::soundIndex`, which matches all 3,000 original `00488D40` cases in `evidence/rng-oracle.json`. The component owns exactly one additional draw for the pain deadline after the service returns. Training chatter-set lookup/content and media playback are still host services, and the FireRescue producer and player callback scheduling remain disconnected.

`player_pain_deadline-check` checks before/equal/after deadline behavior, verifies no pain or stat service and no draw when not due, observes an injected pain-service draw before the single deadline draw, then verifies the stat callback runs after it sees the updated deadline. It also checks unsigned 32-bit deadline storage including a high-bit clock. The stat service remains injected. This is a native control-flow check only: no original `00451640` P-code fixture was produced, so this is not a direct original-vs-native parity claim.
