# Training victim startup integration

The native startup dispatcher now retains a bounded slice of the original victim initialization for the two authored Training victims (entities 191 and 194). It uses the existing class-grouped batch: initial actor-motion choice in pass one, then spawn-candidate choice in pass two.

- `RCS_VictimRescue` construction adds its editor origin first. `RCS_VictimAltSpot` first-pass initialization appends the two alternate points in entity order. `src/startup.h` already reconstructs this ordering from `assets/training/entities.json`.
- Both Training entities have `D_Type=man`. `evidence/original/victims.srf` maps `man` to model 12. `assets/training/actors/vic_man.json` is extracted from the preserved `assets/training/actors/original/vic_man.act` and has six motions.
- In `0045B690`, `00480D00` stores the actor motion count at victim `+0x180`. Six selects the branch that calls `00404B30(3)` and starts the chosen motion at speed 1.0. The native first pass uses this bound once per victim. Model-14-only appearance selection does not apply to Training's model-12 victims.
- `0045D5B0` chooses an index with `00498B30(0, float(candidateCount)-0.01)` then `004B9400` truncation, and copies the chosen candidate's XYZ and heading before `0049DA00` model-hull floor placement. `Random::spotIndex` implements the recovered range/truncation. Native pass two stores the selected candidate entity, authored XYZ and heading, then applies the recovered floor helper through Training `Collision::trace` without an RNG draw.
- The actor base constructor `0049D8C0` zeroes its six hull fields. First-pass victim initializer `0045A3D0` writes max `(24,24,24)` and obtains min `(-24,-24,-24)` through `0042D2B0`. Second-pass `0045D5B0` does not overwrite the hull before the floor call. Saved source: `evidence/startup-constructors/0049d8c0_FUN_0049d8c0.c`, `evidence/startup-initializers/0045a3d0_FUN_0045a3d0.c`, `evidence/item-pose/frame-math-assembly.txt`, and `evidence/victim-floor-assembly.txt`.
- `0049DA00` adds 48 to candidate Y, requests a 1,000-unit downward hull sweep, and stores the returned contact with Y raised by 1. On collision failure it logs and stores the zero-initialized contact plus that final offset. Its wrapper `00492CE0` calls `geWorld_Collision` with contents `0x43` and flags `2`; source export: `evidence/player-tool-pose/actor-parent/00492ce0_FUN_00492ce0.c`.

The source-backed victim-relative RNG sequence is motion draw for entity 191, motion draw for entity 194, spawn-choice draw for entity 191, then spawn-choice draw for entity 194. Floor placement consumes no RNG. Other classes' initialization draws occur between these passes and remain incomplete in the native startup, so this does not establish full Training draw order.

Both authored and floor-adjusted coordinates are retained in native victim startup state. Composition of the helper with the native Training BSP collision is a provisional implementation: `evidence/model-floor-oracle.json` uses fixture contacts rather than real BSP hits, the existing 611 DLL box-hit comparison uses the player hull, and the separate point oracle uses a null hull. `tools/victim_floor_collision_oracle.py` was added to capture Genesis.dll contacts for all six authored points with the victim hull, but bundled Unicorn exited with signal status 132 before it wrote an output fixture; the failed attempt is recorded in `victim-floor-capture-attempt.txt`. Do not treat the native outputs as original-collision verified. No original game process was used. Native victims are still not constructed as Genesis actors, rendered, moved, carried or rescued; the existing RNG, animation, sound and floor-helper component checks do not compare a full Training launch.

The C++ build after this integration succeeds with `cmake --build build -j 4`. The linker reports that Homebrew json-c was built for macOS 27.0 while the target is macOS 13.3. One `--startup-check` run selected entities 192 and 194 and reported native floor hits at Y=-230.9; its output is saved in `native-floor-startup-report.txt`. This is a native smoke inspection only, not a comparison with Genesis.dll.
