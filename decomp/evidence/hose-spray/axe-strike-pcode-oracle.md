# Axe strike original P-code fixture

`axe-strike-pcode-oracle.json` is generated by `tools/ghidra/AxeStrikePcodeOracle.java` from the hash-verified original executable (SHA-256 `4b3b4dc1cc0b05bcb42c8e27ac6f6ca72fe5f7064ca8122fda7d41e7f6d2fc3e`). It runs the actual `00460B90` handler with four controlled cases:

- `strict_time_reject`: first time gate exits before pose helpers or collision.
- `collision_miss`: original pose helpers execute and `00492CE0` is supplied a miss (EAX 0); the handler returns without strike effects.
- `collision_success_empty`: collision is supplied a hit (EAX 1); the handler follows its successful strike path and runs the empty candidate cursor.
- `candidate_hit_flags_1`: collision is supplied a hit, iterator setup supplies one type-4 object, box overlap returns true, and the `0043E2A0` leaf boundary supplies result flags 1.

The fixture preserves the full PE32 input frame at `Player+0x34A4`: vectors copied from offsets `+0x04`, `+0x10`, and `+0x1C`, the `Player+0x34CC` vector, and signed byte `Axe+0x1FC`. Each vector records decimal values and raw binary32 bits. The strict-reject and collision-miss rows retain the simple axis-aligned frame, with side byte 0. The successful empty-list case uses fractional inputs (`+0x04={0.1234567,-0.33333334,1.001}`, `+0x10={1.234567,-2.7182817,0.0001234567}`, `+0x1C={-0.7654321,0.31415927,3.1415927}`, `Player+0x34CC={12.34567,-0.0001234567,-98.76543}`) with side byte 1. The candidate-hit case uses a second fractional input set (`+0x04={-0.27182817,0.5772157,-1.4142135}`, `+0x10={0.9876543,-1.1111112,0.0009876543}`, `+0x1C={2.3025851,-0.6931472,0.70710677}`, `Player+0x34CC={-3.3333333,0.00031415927,42.42424}`) with side byte 0. These nontrivial binary32 values exercise intermediate scaling, addition, subtraction, and both side signs through original P-code. The collision event records all call arguments and the four pose vectors passed to `00492CE0` (`start`, `mins`, `maxs`, and `displacement`), also with raw bits. The simple frame query is `{20,-10,0}`, `{-6,-6,-6}`, `{6,6,6}`, and `{-60,0,100}`. The original binary64 scalar at `004E28B0` remains untouched and is recorded as `0x3fd199999999999a`; this avoids corrupting its upper word with a float write. The source uses the manager/world pointer at `0x00503A7C`.

The original pose helpers all execute in P-code: `00447830`, `00446EE0`, `0049E770`, `00446390`, `00447710`, `0042D050`, and `0043B2D0`. Controlled boundaries are `0045FEC0` gate update; `00492CE0` collision result; string/stat/audio/parent/frame effects; player virtual slot `+0x18`; iterator setup; candidate box test; and `0043E2A0` hit leaf. The candidate hit is a controlled composition point, not original target-list evidence or live Training parity.

## Emulator exit limits

The two successful post-collision cases finish their handler body but cannot complete the emulated C++ cleanup with this synthetic stack. `collision_success_empty` reaches `LAB_004D1521` (`004D1521`) after the `00460B90` body; the fixture stops at that SEH/finalizer boundary and records memory there. `candidate_hit_flags_1` executes the post-hit branch and reaches its final return, but the synthetic return context produces invalid PC `0x00000002` (the previous run also exposed `0x00000004` during that finalizer/return path). The fixture stops at the low invalid-return boundary after recording the body writes. These are explicitly marked in each sample's `exit_boundary`; they are not presented as clean original returns. The miss and strict-reject cases return to the fixture sentinel.

## Schema and inspected dependencies

Each sample has `name`, `exit_boundary`, `frame_input`, `global_threshold_004E28B0_bits`, `pose_helpers_executed`, `collision_calls`, `collision_result_hit`, `writes`, and ordered `events`. Events carry boundary names and exact pointer/stack argument values; the collision event adds dereferenced vectors. `writes` records raw words for Axe attack state/time/position, Player frame inputs, and `DAT_00502E04`.

Dependencies inspected: original Ghidra C snapshot `00460B90.c`; the strike flow and limits in `axe-strike-and-bmodel-hit-audit.md`; bounded iterator representation in `axe-candidate-iterator-module.md` and `src/bmodel_candidate_iterator.h`; and native pose layout/rounding in `src/axe_strike_pose.h`. Exact target-list population remains a runtime input. The fixture does not establish full action cadence, effect rendering, or Training run parity.
