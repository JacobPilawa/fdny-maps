## Decompilation workflow review (2026-10-12)

The current Ghidra → address-labeled evidence → small native component → hash-pinned original-execution fixture → CTest loop is the right fit for a playable native reconstruction. It makes behavior and draw-order claims measurable while keeping unresolved engine callbacks explicit. Keep storing authored facts in Markdown/JSON and raw proprietary data in the existing ignored local directories.

One terminology/tooling distinction matters: `decomp.dev` tracks matching decompilations, where reconstructed code is built with the original compiler/settings and judged against original instruction bytes. The [OpenRAC workflow overview](https://openrac.dev/) describes that byte-match goal; [objdiff](https://github.com/encounter/objdiff) compares relocatable object files and can report that kind of progress. Those percentages would not measure this repository's modern native CMake build or Training behavior parity. Do not add a byte-match percentage to the current viewer. If byte-for-byte PE recovery is also desired, create a separate Windows/toolchain lane with a pinned compiler configuration and object-diff report, and keep that score separate from the native behavior fixtures.

Workflow check (2026-10-12): OpenRAC's [function-matching workflow](https://github.com/OpenRAC/rac1-decomp/blob/main/docs/WORKFLOW.md) supports several useful process choices: verify whether code is library or game code before rewriting it, use disassembler output only as a sketch, iterate one function or family against the original binary, and verify from a clean build. Its build, function-splitting, and MIPS/PS2 toolchain details do not transfer directly to this Windows PE32 game. Current [objdiff documentation](https://github.com/encounter/objdiff/blob/main/README.md) describes configured relocatable-object comparison and automatic rebuilds, and lists x86/x86_64 support; exact compatibility with FDNY's original MSVC object format/toolchain still needs validation before any matching lane is started. `decomp.dev` itself blocked automated page access in this pass, so the recommendation rests on OpenRAC's published description and objdiff's primary documentation. For now, keep hash-pinned original function executions and component-level behavior fixtures as the acceptance evidence for Training; they answer the user's stated runtime goal directly.
