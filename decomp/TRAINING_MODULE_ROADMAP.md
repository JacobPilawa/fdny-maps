# Training module delivery roadmap

Updated 2026-10-12. This is the module-level view of the work; the [checklist](CHECKLIST.md), [mechanics ledger](mechanics.json), and linked evidence keep the address-level details.

## What currently runs

The native app runs a **playable Training scene prototype** with the original map, player spawn, movement, basic collision, doors, selected tool actions, and authored fire/victim visuals. It does **not** yet run the complete source-accurate Training mission. In particular, actor update cadence, several interaction paths, fire/victim lifecycles, mission services, and whole-run RNG order are not connected or verified.

There is no defensible overall completion percentage. Many small source routines already have strong comparisons, but those do not measure how much of a playable mission is integrated.

## How work is grouped from here

Finish one row before broadening the next: source behavior, connected C++ path, module-level scenario, comparison evidence, and a short handoff update. Keep isolated helper checks as support; they do not close a module. Preserve useful findings for the eventual full game, but defer unrelated map-specific routines until a Training module needs them.

The two latest delegated checks refined the first and third rows: FireRescue's local Think route is known but no recurring caller was proved (`evidence/fire-update/root-think-dispatch-query-20261012.md`), and ordinary level loading has no authored `RCS_PlayerHose`/`RCS_HosePath` instance in the preserved Training records. The latter does not rule out dynamic creation, so hose actor work stays conditional on finding a real Training path.

The runtime row now has a composed startup gate: it checks the live native startup phase order, seven routed fires, both victim initialization/spawn passes, the authored door and Player startup script state, and full EVS activation on update four under a selectable fixed RNG seed. It still cannot close the recurring schedule portion. The read-only Ghidra follow-up found no proven caller for Player root `+0x14`, BModel/FireRescue root `+0x14`, or victim child slot 0; a controlled original-runtime trace is needed to recover caller, cadence, and cross-order. See [`evidence/training-startup-integration.md`](evidence/training-startup-integration.md) and [`evidence/scriptactor-common-scheduler-audit.md`](evidence/scriptactor-common-scheduler-audit.md).

The Training Hose valve transaction is now composed in the native input path: saved PropModel candidate order feeds target selection; attach selects Hose Spray, commits the model frame, saves the valve identity and writes the pose-list head; detach changes mode, reselects the first item and suppresses the detach `use` event. The checked sequence loads the two authored `makevalve` entities, runs Valve3 attach → detach → Valve5 attach, and verifies the hose mode, active target, item selection, authored pose position and owner event branch. This closes only that connected action slice. The model's residual axis words still use Ghidra's Java Math substitute for x87 trig; original Player-vs-valve target order/cadence, visible Hose parenting/stream, and other Player interactions remain open. See [`evidence/training-hose-interaction-scenario.md`](evidence/training-hose-interaction-scenario.md).

The liftable source-order core is now recorded in `src/training_liftable_sequence.h`: pickup state writes precede action status and the `use` event; carried-object pose/correction precedes the strict throw-angle gate; throw setup precedes Player action status 4 and carry clear; one externally driven BModel update orders the endpoint write, endpoint flip, `drop`, and timer clear. A standalone C++17 syntax check passes. This is a reusable transaction component, not a live Training integration: candidate registration, carry transform construction, real service adapters, and recurring frame scheduling remain open. See [`evidence/training-liftable-audit/native-sequence-core.md`](evidence/training-liftable-audit/native-sequence-core.md).

The Training Axe callback slice now has native/P-code components for root ACTION press/held, child held ACTION (`+0x18`), child Think (`+0x20`), BModel hit leaf `0043E2A0`, and the strike's pre-collision pose/query.
